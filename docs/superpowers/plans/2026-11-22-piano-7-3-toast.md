## Cosa diventa toast e cosa resta nella barra

- **Toast:** ogni feedback di esito oggi in `m.status` con `isOK` o `isErr`, e il feedback informativo delle operazioni ("letta", "archiviata", "spostata nel cestino", "etichetta applicata", "nuova posta in arrivo", "inviato", "salvato in …", "tema applicato", "impostazioni salvate", errori di op, ricerca, invio, salvataggio).
- **Resta nella barra, con stile neutro `StatusBar`:** stato persistente e contesto: tag della cartella, spinner, badge "N risultati per …" della ricerca attiva, indicatore `⟳ riconnessione…`, connessione fallita con "R per riprovare" (oltre al toast d'errore), banner demo, help breve.
- **Resta nella barra con sfondo colorato:** solo le conferme che aspettano una risposta (invio, scarta bozza, cestino) e il prompt label: sono modali, non notifiche.
- Classificare tutte le ~42 assegnazioni di `statusMsg` in `internal/app` secondo queste regole; nel dubbio, un esito di un'azione è un toast, uno stato che dura è barra.

### Task 1: package `internal/ui/toast`

**Produces:**
```go
type Kind int // Info, Success, Warning, Error
type Model struct { /* pila, id progressivo, stili */ }
func New(st styles.Styles) Model
func (m *Model) Push(k Kind, text string) tea.Cmd   // Error: nessun timer; altri: tea.Tick(3s) → ExpiredMsg{ID}
func (m *Model) Update(msg tea.Msg) tea.Cmd          // ExpiredMsg rimuove quel toast (gli altri restano)
func (m *Model) DismissErrors()                       // chiamata a ogni tasto premuto
func (m Model) Layers(width int) []*lipgloss.Layer   // in alto a destra, impilati verso il basso, Z sopra il corpo
```
- Massimo 3: un `Push` oltre il limite toglie il più vecchio. ID progressivo: un `ExpiredMsg` di un toast già rimosso non tocca gli altri.
- Durata come costante iniettabile per i test (nessuno sleep reale nei test: si invia `ExpiredMsg` a mano).
- Rendering: riquadro con bordo arrotondato colorato per tipo (slot `success`, `primary`/`accent` per info, `warning`, `error`), sfondo e testo dal tema; se il riquadro ha uno sfondo colorato il testo usa il colore calcolato del Piano 7.2 (`onColor`), così vale il test di contrasto. Larghezza massima ~40% dello schermo (minimo ragionevole), testo spezzato su più righe, mai oltre il bordo destro. Margine di 1 colonna dal bordo destro e di 1 riga dall'alto.
- Stili nuovi in `internal/ui/styles` (es. `ToastInfo`, `ToastSuccess`, `ToastWarning`, `ToastError`): se hanno `Background` rientrano automaticamente nel test di contrasto esistente.

**Test:** push e scadenza; pila di 3 con il quarto che toglie il più vecchio; ExpiredMsg stantio ignorato; errore senza timer e rimosso da DismissErrors; posizione X/Y dei layer per larghezze 80 e 140; testo lungo spezzato entro la larghezza.
